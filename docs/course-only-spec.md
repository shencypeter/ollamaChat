## 目標規格

一門課程代表一個實際授課群體。例如「個案分析課程－週一」與「個案分析課程－週三」各自建立課程，各有獨立學員、小組、資源、評量與成績。不再提供課程下的班別、未分班、調班或班別刪除，也不引入替代的隱藏班別或另一個必填課程母層。

| 項目 | 新規格 |
| --- | --- |
| 課程 | 以 course_id 為教學與授權邊界；沿用名稱、代碼、學期、擁有者及狀態。不同授課群體各自建立課程。 |
| 學員 | 直接加入課程，不再安排班別；同帳號可參與多門課程，各課角色互相獨立。 |
| 小組 | 直接隸屬課程，只能加入本課有效學生；每人每課至多一個有效小組，可未分組；組名在同一課程唯一。教師／助教安排。 |
| 資源 | 以課程為使用範圍，本課有效成員可閱覽／下載，其他課程成員不因同名課程取得權限；移除「全班共用／限指定班別」選項。 |
| 評量 | 測驗、PDF 作業與案例直接屬於課程，學生提交、標準答案保密、人工／客觀評分與正式發布政策沿用。 |
| 成績／統計 | 以課程有效學生計算；個人及課程平均、權重、排名／學號排序依各既有功能沿用，沒有班別篩選。 |
| 權限 | 課程擁有者管理課程成員，課程教師／助教管理教學內容及小組；學生只讀允許內容。封存、學生體驗與正式／練習隔離依最新政策沿用，不能藉此次簡化放寬學生答案或報告權限。 |

### 介面與操作

- 課程頁籤改為「課程學員／小組」。學員名單保留學號、姓名，移除班別欄、分班篩選、班別設定、調班與班別刪除確認。
- 小組表單移除班別選擇；候選人直接取本課有效學生。沿用未分組及已加入小組的檢查與明確錯誤提示。
- 資源上傳、卡片與預覽移除班別選擇／標籤；文件名稱、原檔名、預覽、下載計次與版本衝突保護保留。
- 建課流程保留現有欄位；可在課程名稱／代碼中區別授課時段。同學期 code 必須唯一，例如 LEARN-101-MON 與 LEARN-101-WED，名稱可以相同。不因取消班別自動修改既有代碼。
- 原班別 schedule 為文字說明；若有真實值，遷移時保存在映射清單，必要時再評估課程層級的選填上課時間欄。新增時間欄、課程改名介面不視為本次使用者已另行要求的產品功能。
- 「調班」不自動變成跨課程搬移學生作答。加入另一門課程與原課程紀錄分開；原提交與成績仍留在原 course_id，不自動攜帶或重算。

### 課程獨立與禁止跨課程資源共用（2026-11-03 補充）

使用者已明確取消跨課程共用資源：每門課程皆獨立，資源只能隸屬一門課程，不提供跨課分享、單一資源對多課程授權、共用檔案庫或跨課同步更新；取代前版「跨課共用另案」的規劃。

同一教材需用於不同課程時，必須在各課程分別上傳，產生各自獨立的資源紀錄、名稱、版本與下載次數；任一課程的修改或刪除不影響其他課程。有效成員資格分別核對：同名課程、同一授課教師或參與另一門課程都不會自動取得本課資源權限；同帳號可同時參與多課，仍依各課資格分開存取。學員、小組、評量、提交與成績也各以所屬課程管理，不因教材內容相同而串連。

本次不新增跨課資源分享介面、授權關聯表或跨課檔案連結。複製評量並非此資源規則的新增需求，不在本次實作範圍。

## 既有資料轉換規則

規格階段未連線盤點即時資料庫，不以舊紀錄推斷目前班別數、人數、資源或提交狀態。實作前需唯讀盤點並產生映射／衝突清單：各課班別、含停用者的成員關係、同課重複組名、有效／歷史組員、限定資源與預覽／下載數、上課時間，以及全部評量／提交／成績關聯；清單不納入私人答案或檔案內容。

1. 沒有班別、只有空班別，或已確認只有一個實際授課群體：優先保留原 course_id；有效學員直接沿用，小組保留原 group_id 與關係／歷史，不因取消班別清空小組。
2. 同一課程含多個真實授課群體：不能僅刪班別然後視為已完成。先明確決定保留為單一課程，或建立獨立課程並核定成員、資源及評量映射。不可猜測班別與未分班學生去向；本規格不授權自動拆課或刪除真實內容。
3. 原班別限定資源：在明確決定目標課程與可見對象前，保留原限制。不可將所有 section_id 直接設 null，造成原本其他班／未分班成員立刻讀取。若要擴大至原課全部學員，須把影響資源與對象列入實作前可審核轉換清單並取得明確授權。
4. 同課不同班可能有同名小組，或歷史／舊資料存在有效組員重複：先列出衝突並解決，再建立課程層級唯一規則；不得自動合併組別、刪組員歷史或丟棄提交關聯。
5. 全課共用資源的檔案、名稱、版本、下載次數及原上傳者保留。若既有資料轉換涉及拆課，資源須明確配置至目標課程；多課需要相同教材時，各課建立獨立資源，不保留跨課共用連結。新增資源下載數由 0 開始，原資源歷史下載數保留且不複製冒充新下載；原資源去向需列入映射清單。
6. 既有作答快照、正式／練習紀錄、評閱、稽核與成績保留原關聯；不藉刪班端點執行退役，因該端點會刪除小組／成員關係，與本次保留目的不同。
7. 先備份／保留回復映射，再以交易、筆數與外鍵驗證完成轉換。可採先停用舊寫入、相容部署，再於資料完成轉換後以新 migration 移除舊結構；最終不留可操作的班別層級。資料已搬移的情況不能僅回退 UI 當作完整回復。

## 驗收與建議順序

先盤點與解決映射／可見性／重名衝突，再實作 UI＋API＋新遷移，最後部署同版前後端並清理 QA。整體屬中等範圍結構簡化；主要不確定性是既有多班與限定資源轉換，尚不能僅依程式檔案數承諾工時。

- 不再顯示或提供班別建立／調整／刪除及班別限定資源操作；直接呼叫舊端點也不可寫入。
- 無班別資料時即可建立小組、安排本課學生；每人每課一個有效小組，不同課程獨立，同課組名唯一。
- 同教材分別上傳至兩課時，資源 ID、版本與下載次數獨立；修改／刪除其中一課資源不影響另一課，不提供跨課共用介面或 API。
- 本課有效學生／教學者可依角色存取本課資源；他課 ID、未加入、停用成員及學生體驗寫入維持拒絕。預覽不計下載、成功下載才計一次；列表／摘要／預覽／下載範圍一致。
- 遷移前後課程／小組識別、正式及練習提交、成績與檔案內容核對無意外變動；限定資源不意外擴權。重名、多班、未分班、停用學生與舊小組提交皆納入轉換測試。
- 回歸客觀題批改、申論人工評分、正式發布、PDF 私密／檔案預覽、案例歷程、權重平均及正式／練習隔離；教師桌面與學生手機介面驗證。
