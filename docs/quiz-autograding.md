# 測驗自動批改

2026-10-30，適用目前 /quizzes 的線上／課後測驗新提交，不追溯覆寫舊人工成績。

## 規則

| 題型 | 評分 |
| --- | --- |
| 是非／單選 | 答對滿分，答錯／未答 0 |
| 多選 | 選項集合全對才滿分；漏選、多選錯項、未答 0，順序無關 |
| 申論 | 教師／助教逐題人工給分，客觀題分數不可改寫 |

逐題配分可留白，剩餘滿分平均分配到未指定題，保留兩位小數、最後未指定題吸收餘分。全部指定時必須加總等於測驗滿分。申論仍需填答後才可提交，客觀題留白可提交為 0。不得以學生提交的答案鍵或分數評分。

## 操作與發布

1. 出題設定題型、客觀標準答案、滿分與選填配分，發布後鎖定。
2. 提交交易建立不可改寫快照及 quiz_grading 逐題判定。純客觀題自動完成分數；混合題顯示申論待評。
3. 教師開啟正式提交，只需輸入申論題分數。所有申論須填完才可儲存完整評分草稿，暫不提供逐題部分儲存。系統驗證每題上限及合計。
4. 純客觀題只需「發布自動評分成績」；混合題人工儲存後發布回饋。正式發布前學生只見狀態，不見正誤／自動分數；發布後可見各客觀題結果及總分，同步原成績簿。

練習純客觀題自動結果立即可見，混合題仍切回教學視角評本人申論；不寫正式成績或班級統計。PDF 作業仍人工閱讀評分，案例仍文字回饋不計分；不使用 LLM。隱藏的舊 exams 模組不在本次擴充。

## 資料與相容性

012_quiz_autograding.sql 已套用：quiz_grading.snapshot_id 真實 FK 對 submission_revisions，保存每題配分／判定／自動得分；grades.essay_scores 保存申論分項。系統評分 grader_user_id 為 NULL，畫面顯示系統自動評分，避免冒用人員；人工仍記錄實際評閱者。發布及樂觀衝突規則沿用。

GET /api/assignments/{id}/revisions/{revision}/quiz-grading 驗證提交所有權與 practice namespace，學生發布前遮蔽自動分數／正誤，永不回原始答案鍵。正式 grade API 與私人 practice grade API 都驗證申論題集合／範圍／合計，不接受客觀題改分。

舊提交無 quiz_grading 時沿用舊人工流程，不自動重新評閱或更改歷史。新提交立即適用，無需重新建立已發布題目；舊題目配分未設時依現有滿分均分。
