# 下一輪建議

更新：2026-11-16。以下是建議，並非教授核准的新增需求。

## 已完成及仍有缺口

已完成四階段共用方法與分類規則、43碼詞彙表、課內／Studio各自相容的結構回饋與版本化原文標註、底線／圖例及相關確定性測試。仍不完善的是實際模型對證據與時點的穩定判讀、長文offset品質，以及課內缺少獨立可信病例的事實核實能力。第一輪即時12個合成情境全部複製JSON示範，已移除prompt的具體示範；此修正不能代替重跑與教授驗收，最新結果見[03-evaluation-results.md](03-evaluation-results.md)。

最高優先回歸風險是提示佔位內容複誦、把分類認作正確、缺來源仍捏造遺漏、把後期狀態當初始或病前狀態，以及把聯絡人當照顧者。標註方面應持續檢查重複片語、emoji、重疊、多碼、修訂版次與較長prompt壓縮對話空間；既有統計／教師查閱與Raw不注入階段指令亦須保留。

## 優先完成的教學驗收

1. **教授審閱少量實際回覆。** 選一份已核准、去識別且來源清楚的案例，四階段各含完整、部分、籠統、錯置、等義改述、無據主張、資料未提供、來源矛盾及修訂情境。逐項檢視是否引導修正而非代寫；特別檢查初始／後期GCS、C2／C5、聯絡／照顧角色與合法多碼。不以確定性fixture通過當臨床效果已達成。
2. **釐清可信案例來源。** Studio既有案例payload可供核實；課內聊天目前只有學生歷史與目前作答，無獨立病例。先由教學負責人指定合法去識別教材與版本，再決定如何沿現有內容路徑提供；在此之前保留無法核實提示，不要求學生猜補未載資料。
3. **確認少數編碼界線。** 優先回答非法藥物、診斷性處置／EEG、key person與D3b、跨時點B4/C1及no coding範圍。用短小概念示例確認，不將整份病例答案公開或嵌入prompt。
4. **核實新提示的模型負荷。** 用實際部署profile重複測試四階段，記錄Schema成功、offset有效率、被拒標註比例、回饋篇幅、實際可取得的token及延遲；以現有metrics白名單為限。長文、中文／英文、emoji、重複語句、同span多碼及來源缺席需覆蓋。若模型無法穩定提供offset，先評估保守少標註，不以猜位置修補。

建議教授用一份簡短審核表判「證據正確／時間分類適切／未捏造遺漏／保留不確定／沒有代寫／標註有教學價值」，保留可接受與需修改的去識別例子。驗收不必新增成績、過關或第五階段。

下一輪需要的材料：一份來源一致且可合法用於教學的去識別病例、各階段少量由教授核定的完整／部分／模糊／錯置及等義例句，以及能展示照顧角色不明、前後測量不同、未測與陰性差別的短句。可採合成作答；若使用學生答案，先確認去識別與授權，不把原文寫入持久化測試日誌。

## 可選的後續改進

| 建議 | 教學效益 | 前提 |
| --- | --- | --- |
| 由教授核定少量等義與邊界例句 | 降低只比關鍵字或把合法多碼判錯 | 先解決[待確認事項](04-open-questions.md)，例句不得含真實學生答案 |
| 在既有回饋上區分常見錯置與資料不足的彙整 | 讓教師找出共同困難 | 先驗證模型標籤可信度與資料使用權限，避免把不可靠分類當正式統計 |
| 依教授審閱結果調整標註密度及先後 | 降低長答案的視覺與閱讀負荷 | 不變更原文、版本關聯及底線不代表正確的語義 |
| 對較長答案研究更有效的提示大小或模型輸出上限 | 保留更多實際學習內容的對話空間 | 以現有context檢查及真實量測決定，不默默截斷歷史 |

本輪刻意不做：新病例管理／檢索架構、第五階段、模型微調、換供應商、自動診斷、成績、過關、改寫歷史回覆、以參考病例當通用答案鍵，以及未經驗證的模型profile覆寫。課內空白API仍依原契約回400，沒有為模型空白提示改變學生提交流程。

單一最有用的下一步：由教授對指定去識別案例的四階段實際回饋與標註做一次短輪審閱，先確認證據與分類界線。
