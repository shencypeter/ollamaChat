使用者提供B階段貼入A病前內容的畫面：分類辨識出A，但AI只稱讚人口學資料，沒有指出錯置。原元件也沒有目前階段資訊，所有類別只畫底線。根因分成模型上下文／措辭與UI呈現兩部分。

- CaseChatPrompts升為professor-four-phase-20261116-v3，最前列明目前ABCD階段；主要作答屬他階段時必須說明目前階段、原文實際分類及修改方向，不能只稱讚。必要背景引用及合法多碼不概括判錯。
- 修正「無案例則unverified」可能掩蓋分類錯置的歧義：沒有可信病例限制的是事實核實，不妨礙對明確階段位置給misplaced提示；仍不可宣稱臨床內容正確。
- CaseFeedbackAsync增加stage-aware相容overload，CaseAnalysisChat由伺服器選定stage傳入currentStage／currentPhase／currentStageLabel；不從學生文字猜目前階段。原始answerText、Raw及舊provider入口保留。
- 既有Studio升為case-text-feedback-phase-v3，原schema欄位保持；以已儲存answer.stage給currentPhase，summary／improvements／nextSteps明確說明錯置或必要背景。
- 新UI把同階段分類做淡色背景、其他階段做底線。回饋區的PhaseAlignmentNotice明確標為系統依有效標註整理，非AI回覆原文；舊歷程不重寫／不回補模型說法。只有未被標註不等於缺漏。

三個模型profile及抽樣不改，沒有Migration或正式資料寫入。實際IAN02小樣本與剩餘語義限制見03，不能以格式成功宣稱專業驗收。

共通規則採等義與語境判讀、已知／推論／假設／未提供／矛盾分層；只針對實際有來源的重要資料談遺漏。五類回饋標題保留教授原本的彈性，不製造問題補滿欄位，提示回查資料類型而非代寫完整答案。修訂只評最新版本，不拿歷史舊內容補足目前答案。

`TeachingInstructions(stage)` 提供共用方法與該階段規則，不附課內聊天JSON契約。既有 `Services/StudioFeedbackContract.cs` 重用此入口，提示版本為 `case-text-feedback-professor-v2`，依應用提供的案例資料核實，保留原有summary／supportedPoints／improvements／nextSteps欄位，另以選填annotations相容擴充。`Get(stage)` 則加入課內聊天專用 `{feedback, annotations}` 內部JSON要求，供新結構解析後再沿用文字回饋展示。Raw一般對話仍不使用階段提示或此Schema；舊作業／測驗評閱亦未改成課內聊天契約。

新增標註只針對目前版本精確原文；持久化及公開表示維持UTF-16、0起算、end exclusive，支援同span多碼、相鄰、重疊、重複片語。模型內部表示採text精確引用及occurrence（0起算、由左至右完全相同的出現次序，允許重疊匹配），由伺服器計算UTF-16範圍，不要求模型做位置算術、不猜位置或正規化。課內模型請求的最新user由應用封裝為JSON，answerText解碼後才是學生原文，outputRequirements為簡短格式提醒；範圍不相對於JSON包裝或轉義字元。資料庫仍保留原始作答，歷史不因此重寫，Raw不變。伺服器以43碼詞彙表白名單驗證；A2c、B2c、C5子碼及自行發明的碼不接受。模型最多回48筆，說明最多200個UTF-16單元，回饋最多12000；預設unverified不當成答對，另可標unsupported或misplaced。無可信案例或來源矛盾時保留unverified及限制說明。引用與次序仍是不可信模型輸出；既有明確start/end表示保持相容驗證，同一筆混用引用次序與位置表示則拒絕。完整驗證見[06-annotation-ui.md](06-annotation-ui.md)。

三個 `Configuration/Ollama/` profile、抽樣、模型、既有transport相容旗標保持各自設定。新課內結構路徑使用獨立Schema，不把此契約注入Raw。提示保持精簡並以UTF-8大小上限回歸檢查，避免光系統詞就超過既有12KB保守對話預算；此上限不是token量或回應延遲的實測。

限制：課內聊天並未另行取得可信病例；不能藉提示宣稱已有完整病例核實。Studio有案例來源，也仍需專家審閱事實與分類品質。空白課內API原有400驗證保持；模型對空白的建設性指引僅適用實際收到此內容時。版本提高後，舊失敗訊息依既有策略不得沿舊prompt重試，需新對話；歷史已完成回覆與原文不回寫。確定性測試只驗證提示／Schema／驗證／UI行為，實際模型表現另見[03-evaluation-results.md](03-evaluation-results.md)。

本次文件已記錄規則演進、實作解讀及未決項目，沒有將病例數值、標準答案或真實學生答案放入持久化文件。

### 本輪即時模型發現與修正

第一輪12個合成情境確實呼叫部署模型；模型全部複製提示中的JSON示範佔位內容，虛構標註被精確原文驗證拒絕。這不是臨床回饋通過。已移除課內prompt內整個具體JSON示例，改為欄位／行為說明，以API提供的Schema定義結構，並要求feedback寫本次實際教學回饋。測試也防止示範佔位回流。重跑結果、模型與量測範圍以[03-evaluation-results.md](03-evaluation-results.md)為準，不以提示修正本身宣稱模型行為已改善。

第二輪12次合成呼叫在移除示例後回饋已有變化，但仍出現初始GCS誤用、要求不存在資料及偶發英文，提出的15筆標註全部被精確原文驗證拒絕。隨後以最小provider封裝釐清answerText與格式要求，提示亦明確只標解碼後answerText；這是模型輸入澄清，不修改公開提交API或原文儲存。現階段不得宣稱部署模型已通過臨床回饋或標註語義驗收。

第三輪12次實際呼叫使用answerText封裝，語言表現改善，但仍有初始GCS誤用、不實遺漏及修訂內容複誦；模型即使常能引用原文，提出的位置仍全部未通過。最後將AI專用標註表示改為精確text加occurrence，由伺服器嚴格定位；原文、公開範圍與歷史相容性保持。這只改善可驗證定位方式，不解決臨床推理品質；最終重跑結果仍以03報告為準。
