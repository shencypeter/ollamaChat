## 操作

1. 課程頁建立作業時，每題可選申論、是非、單選、多選。申論仍使用 textarea；客觀題需設定標準答案，單／多選輸入每行一個選項。新增與修改選項後需重新勾選答案，避免位置錯置。發布後題目與答案鎖定。
2. 課程頁下方有「課程檔案資源」「課程小組」「考試評測管理」。教師／助教上傳教材、分配小組及建立考試；學生讀取資源、小組與已發布考試。
3. 作業頁下方「作業提問與答覆」：學生提問預設私人，教師／助教儲存答覆並選擇是否公開。公開會包含提問者姓名，介面先告知；可再改回私人。封存課程停止新增／修改。
4. 帳號設定頁可「登出並切換帳號」，回登入頁後輸入另一個本人帳號。沿用原登出 API、清除 Cookie／session、本機身份／學生體驗狀態及 CSRF token。側欄原入口仍在。
5. 教授的成員管理可新增或修改學號；學號唯一、選填，不代填既有真實學生資料。
6. 考試可建立／編輯草稿（版本保護）、發布與關閉。正式學生明確儲存草稿，完成所有題目後一次提交。成績清單由教師／助教檢閱並人工評分（0–100、最多兩位小數），儲存後本人立即可見。清單可按學號或分數排序，同分 dense rank（1、1、2），未評分無排名。

## API 與權限

- `GET /api/courses/{course}/resources`：有效成員列出檔案資訊；不回傳本文。
- `POST .../resources`：教師／助教 multipart 上傳，每份 1 byte–20 MB，存 PostgreSQL bytea。
- `POST .../resources/{id}/download`：有效成員下載附件，成功找到檔案才原子增加下載請求次數；不是獨立人數或完成儲存次數。不以 GET 修改計數；寫入仍有 CSRF。
- `GET/POST .../groups`、`PUT .../groups/{id}`：有效成員讀取，教師／助教分配本課程有效學生。保留離組紀錄，目前允許跨多組，不提供共同提交。
- `GET/POST /api/assignments/{id}/discussions`、`PUT .../discussions/{discussion}`：學生只能讀本人／公開問題與新增私人問題；教師／助教可答覆及控制公開。
- `GET/POST /api/courses/{course}/exams`、`GET/PUT .../exams/{id}`、`POST .../{id}/publish|close`：考試管理與狀態轉換。草稿不給學生；學生在開放前收不到題目，任何時點都收不到標準答案。
- `GET/PUT .../exams/{id}/attempt`：真正課程學生的本人答案；版本衝突 409，提交後禁止重寫；伺服器檢查截止／關閉／封存。教師學生體驗無考試寫入權限。
- `GET .../exams/{id}/results?sort=student|score`、`PUT .../results/{attempt}`：只限課程教師／助教，完整清單不給學生；評分亦用版本保護。
- `PUT /api/accounts/{id}/student-number`：平台教授維護唯一學號。
- 原作業形成性 `ai-feedback` GET／POST 一律 403，頁面不載入／呈現 AI，也不在提交確認要求 AI。保留舊資料與內部實作供歷史參考；獨立 `/api/ai/*` 及各模型設定不改。

標準答案在管理端讀取時才加入回應；正式學生與 staff practice 都不回傳。答案格式為選項索引陣列（是非固定「是」「非」），後端拒絕重複、越界、多選單選錯誤或不完整正式提交。申論答案仍為原文字。
