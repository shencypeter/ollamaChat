# P1：作業修訂、人工評閱與規準

更新：2026-10-27。本次依使用者提供的 P1 任務擴充，不呼叫 AI 進行評分。

## 實作盤點與架構決策

現有系統為 Vue 3／Vite、ASP.NET Core 8 Web API、Npgsql 直接 SQL。沒有 DbContext 或 EF Core 遷移。P0 已有作業草稿／發布／關閉、UTC 期限、逐題草稿歷史、課程授權與版本衝突保護。

P1 延用上述結構，新增整份提交快照、可選修訂、規準管理與人工評分。未另引進 EF Core；資料庫變更以既有校驗碼與交易式 SQL 遷移管理。這與任務文字中「EF Core migrations」的工具要求不同，目的是避免平行遷移歷史及不必要的資料存取重寫。

## 作業政策

- 舊作業預設 `allow_revisions=false`，維持提交後鎖定。
- 草稿編輯器可設定滿分（預設 100）、規準與允許修訂；發布後上述設定、題目與時間均鎖定。
- 允許修訂的作業，在發布中、課程未封存且開放／截止時間允許時，可提交新版本。
- 已提交後的修訂直接提交新快照，不以草稿覆寫教師正在檢閱的內容。未儲存文字仍有離頁提醒。
- 每次成功提交產生完整 `submission_revisions` 快照，包含提交序號、作者、時間、逐題文字及答案版本識別。
- 整份提交序號與逐題草稿版本不同。作業列鎖與 `expectedVersion` 防止同時更新覆蓋；同一舊版本的競爭提交只能成功一筆。
- 歷史快照不可 UPDATE，排序為提交序號由新至舊；前端提供兩版本並列比較。

## 人工評分與發布

- 僅課程有效教師或助教可評分；平台角色本身不授權存取其他課程。
- 評分綁定指定的整份提交版本，新提交不繼承舊版本分數。
- 使用既有 `grades` 表保存每次修改，記錄評閱者、時間、回饋、規準項目及前筆評分識別；儲存草稿不覆寫舊列。
- `expectedGradeId` 必須符合目前最新一筆，否則回傳 409。
- 儲存與發布是兩個動作。只能發布目前最新評分；學生只看得到自己提交版本的已發布紀錄。
- 新修訂的評分草稿不隱藏或覆寫原已發布紀錄；待再次發布後新增可見評閱。頁面保留已發布變更歷史。
- 教師可評閱較舊提交版本，介面明確指出其版本。最新提交的名單狀態可能因此仍顯示待評分。
- 分數須介於 0 與作業滿分，最多兩位小數；此處與 AI 的 1–4 分契約分開。

## 規準版本與計分

- 每門課程可建立多份規準，並於同課程不同作業重用。
- 每份規準具有名稱與 1–20 個項目。項目包含說明、正權重（最多三位小數）及 1–4 級描述。
- 尚未關聯任何作業且未使用的草稿可原地編輯並增加版本號；已關聯作業或使用過的規準，編輯時建立同 family 的新版本及新識別碼。
- 作業關聯固定版本，不會隨新規準自動切換。發布時將規準標記為已發布；舊評閱依據不變。
- 使用規準時每個項目都必須且只能有一個合法級別，總分由伺服器驗證：`round(Σ(權重 × 級別) / (4 × Σ權重) × 作業滿分, 2)`。
- 因而所有項目 4 級得到滿分，所有項目 1 級得到滿分的四分之一。零分可用於未採規準的直接評分；若教授需要零級或其他等級分數映射，須另行確認並擴充。

## 資料庫變更

`Database/003_teaching_workflows.sql` 為附加遷移：

- `assignments` 新增修訂政策、滿分及規準關聯。
- `rubrics` 支援課程層級與 family 版本；舊 question 關聯仍保留，但允許為空。
- 新增 `submission_revisions`，並替既有個人已提交作答建立目前版本快照。舊的逐題草稿歷史不改寫。
- `grades` 支援整份提交版本、發布時間及規準分項；舊逐題成績關聯仍相容。
- 加入唯一約束、索引與快照禁止更新觸發器。

從根目錄設定本地連線後執行：

```powershell

dotnet run --project AiTeachingAssistant.csproj --no-launch-profile -- --migrate
```

網站啟動不會自動遷移。不得修改已套用的 SQL 以修正後續結構；新增下一個遷移。

## API 與畫面

課程頁新增規準建立／編輯；作業草稿新增修訂與計分設定；作業頁新增提交快照選擇、兩版比較及人工評分／發布區塊。

| API | 功能 |
| --- | --- |
| `GET /api/assignments/{id}/submissions/{submissionId}/revisions` | 授權學生本人或課程教師／助教讀取提交快照 |
| `GET/POST /api/courses/{courseId}/rubrics` | 課程教師／助教列出及建立規準 |
| `PUT /api/courses/{courseId}/rubrics/{rubricId}` | 編輯未使用規準或建立新版本 |
| `GET /api/assignments/{id}/rubric` | 課程成員讀取此作業固定規準 |
| `GET /api/assignments/{id}/revisions/{revisionId}/grades` | 教師讀完整歷程；學生本人只讀已發布紀錄 |
| `POST /api/assignments/{id}/revisions/{revisionId}/grades` | 教師／助教儲存新人工評分草稿 |
| `POST /api/assignments/{id}/revisions/{revisionId}/grades/{gradeId}/release` | 發布目前最新草稿 |

沿用 P0 的建立、發布、關閉與學生儲存／提交 API；所有寫入均有 Cookie 與 CSRF 保護。

## 可重複的 11/15 示範

先套用遷移、建置前端及啟動網站。以下只建立有 run 識別的合成帳號與課程，不變更真實紀錄；若已有 QA 狀態檔，工具拒絕覆寫，須先確認並清理上一輪。

```powershell
dotnet run --project tests/PortalSmoke -- D:/AI_TeachingAssistant --demo
```

帳號、隨機密碼、課程與作業識別保存於被 Git 忽略的 `.codex-build/portal-smoke.json`，僅供本機讀取，不貼入文件。預建作業為草稿，具有題目、未來期限、規準及修訂政策。

1. 用合成教授帳號登入，開啟示範課程。可檢查既有示範草稿，或另外建立規準與作業。
2. 確認題目、期限、規準與允許修訂後發布。
3. 學生登入，第一次提交答案，再修改並提交第二次。
4. 教授／助教登入，查看作答，選擇第二次及第一次提交進行並列比較。
5. 為選定版本設定規準級別與回饋，儲存草稿。學生此時看不到未發布回饋。
6. 教授明確發布回饋。
7. 學生重新載入，查看已發布分數、回饋與版本；切到舊版確認沒有繼承新版本成績。
8. 視需要關閉作業，確認不能再提交。

確認不需保留本輪合成資料後：

```powershell
dotnet run --project tests/PortalSmoke -- D:/AI_TeachingAssistant --cleanup
```

清理前核對帳號 run 與 email、課程擁有者及作答所有者；發現非本輪學生作答時拒絕。清理評分、快照、規準與依賴紀錄的交易不應用於真實課程。

## 限制與後續

- 沿用 SQL 遷移，沒有產生 EF Core Migration 類別；這是架構相容性決策，並非聲稱已完成 EF 工具鏈。
- 無正式環境部署、負載／長時間壓力、備份還原或無障礙認證驗收。
- 未支援規準跨課程分享、任意等級分數映射、遲交例外、撤回／重新開放、附件與分組。
- 正式提交後修訂需直接提交新快照，沒有私有的「已提交後修訂草稿」伺服器流程。
- AI 整合、分析儀表板、公告、通知及研究／IRB 流程不在本次範圍。

## 2026-10-28 後續擴充：私人形成性回饋

學生首次正式提交前可對已儲存的單題草稿要求 AI 回饋；既有人工評分、發布及提交快照政策不變。AI 僅為私人練習，不寫 grades，也不讓教授／助教自動看到。詳細規格、004 遷移與實際測試見 [形成性回饋文件](formative-feedback.md)。以上原 P1 的「AI 不在範圍」保留為歷史交付範圍，不代表後續仍未實作此私人練習功能。

## 2026-10-29：教師／助教學生體驗

教師與助教可切換學生視角，使用本人隔離的 practice 草稿、形成性回饋與提交，不變更帳號／課程角色，不計正式提交或成績。005 遷移新增 submissions.is_practice；原學生流程保留，staff 仍不能讀正式學生私人回饋。一般對話記憶另分 namespace，practice 不擷取或顯示原始 Ollama 診斷。完整政策、限制及驗證見學生體驗文件。
