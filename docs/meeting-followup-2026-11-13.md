# 11/13 會議逐字稿後續實作

本輪承接已核准的畫面差距，增量補齊跨課訊息、行程、紙本考後登分、小組批改及課程首頁進度。沿用課程授權、單元、PDF 繳交快照與同一套課程成績簿；不重建作答或成績資料。

## 已實作的行為

- 個人首頁新增跨課訊息與行程，可選課程、瀏覽訊息前後頁。訊息包含已發布公告、教材、評量、本人已公布成績，以及教師課程的討論更新；行程包含作業截止、線上正式考試與已設定時間的紙本期中／期末考。未排日期的考試不猜測日期，逾期未交仍在原學習待辦。
- 課程側欄新增「課程公告」，提供草稿／發布、編輯與版本衝突檢查。學生只讀本課公開公告；教師及未被停用教材權限的助教可管理。封存、學生預覽與其他課程拒絕寫入。公告使用純文字，不執行 HTML。
- 正式考試預設紙本期中／期末考登分：直接建立既有 `course_grade_items`，提供完整有效學生名冊、滿分、選填考試時間、全班草稿及整班發布。空白與 0 分分開；必須所有有效學生已儲存非空得分，且名冊、項目及每筆分數版本均吻合，才能一次發布。學生只見本人已發布值，後續草稿不取代發布快照。原線上考試保留於明確標示的收合區。
- 小組 PDF 批改改為左側完整小組清單、右側單組 PDF 與評分，已繳在上、未繳在下，提供前後組切換。未交畫面唯讀，不建立空白繳交。預設只填基礎成績、全組同分；個別調分與組員回饋分別收合，已有調整會展開且不因收合而遺失。調整原因與原快照、稽核保留。
- PDF 作業從逐份發布改成同作業全班一次發布（個人／小組皆適用）。缺交、退回、缺分、缺快照或版本不符全部拒絕，成績簿同步與事件紀錄同交易提交。舊的單份 `publish=true` 請求明確拒絕。
- 課程首頁在單元前呈現本課概況：教師看有效學員與正式提交統計；學生看本人提交進度及待公布數，連回原統計／進度頁。受限助教與學生預覽不額外取得統計／個人資料。

## 資料庫與相容

Migration `036_announcements_agenda.sql` 新增 `course_announcements`（課程、作者、純文字、草稿／發布、版本及時間）、`course_grade_items.scheduled_at` 與索引。原評分項目、來源 ID、配分、歷史權重、作答與發布快照保持。

另新增 `course_grade_scores.published_at` 與 trigger：新發布或公開得分變更才更新時間；未公開草稿修改保留原發布時間，撤回公開值則清空。既有公開分數以原 `updated_at` 回填，屬近似歷史時間，不宣稱可還原過去精確發布時刻。此 trigger 覆蓋既有 API、成績同步服務及示範工具的寫入，避免不同發布路徑漏記。

## 設計假設與仍保留的限制

- 公告管理沿用助教「教材與公告編輯」能力，不新增平行權限系統。
- 跨課訊息是按時間排列的活動流；既有側欄未讀通知計數不包含公告，也不因打開首頁自動標成已讀。
- 行程從台北時區今日起排列，最多 100 項並提示篩選；沒有排日期的項目不出現在行程。一般線上作業不包含不支援的歷史 group 模式。
- 組員互評與同分意願仍是教師參考，不自動調分；本輪沒有新增獨立的同分調查模式。
- 缺交／退回／未評分的 PDF 必須先依原作業流程處理，再發布；沒有用虛構 submission 或將空值偷偷視為零分。紙本名冊若應給零分，教師須明確填入 0。
- 原線上正式考試仍沿用既有獨立作答及即時評分機制，與本輪紙本成績簿項目不同；沒有搬移舊考試或默默重算其成績。
- 新手教師實際操作的可用性訪談、完整週／月曆、公告附件及公告未讀追蹤仍是後續工作。

## Demo 驗收順序

1. 教師進入課程「課程公告」，先存草稿，再發布；學生首頁應出現該課與作者的公告，從訊息可回到指定公告。
2. 在「正式考試」新增紙本期中考、滿分及時間；確認首頁行程可回到該考試。原線上考試訊息則展開並選取線上考試區。
3. 依全班名冊登分，保留一人空白，儲存草稿；學生應讀不到新分數，整班發布應被阻擋。明確填入 0、儲存，再一次發布。
4. 同一人修改已發布後的草稿，學生仍看原公開分數，首頁公開成績時間也不改變；明確重新整班發布後才讀到新值。
5. 從單元進小組 PDF 批改，切已交／未交組；未交組不可評分，已交組只顯示所選 PDF。給基礎分、展開一位組員調分與原因，再收合儲存，確認調整保留。
6. 全部指定組繳交且評分完成後一次發布 PDF 成績；學生僅讀自己的公開最終分數。教師／學生返回課程首頁可看本課進度，跨課資訊仍由我的首頁查看。
