# 教材改以單元收納設計

日期：2026-11-11  
狀態：待使用者確認

## 目的

以課程單元作為教材唯一的主要分類與收納層級，取消教材管理介面的 tag 分組，讓教師與學生沿著「課程 → 單元 → 教材」閱讀內容，避免 tag、授課日期與單元同時形成互相競爭的分類方式。

## 採用方案

採用嚴格單元歸屬。新增教材必須選擇單元；沒有單元時禁止新增並引導教師先建立單元。教材管理清單依單元排序與分組，每張教材卡可直接改變所屬單元。

曾考慮但不採用：

- 僅移除 tag、仍允許未歸類：改動較小，但無法建立穩定的課程學習結構。
- 自動依 tag 或日期建立／推測單元：可能產生錯誤歸屬，不符合保守遷移原則。

## 介面與行為

- 教材管理頁移除 tag 輸入、建議、編輯、chip、篩選及「未標記」狀態；搜尋改為教材名稱、原始檔名與教師摘要。
- 移除「依授課日期分組」。授課日期仍保留為教材資訊與日期篩選條件，不再作為清單群組。
- 教材依 `course_units.sort_order` 分組，單元內維持選定的日期／上傳排序。單元標題顯示教材數量與說明。
- 新增檔案或 YouTube 回放時「所屬單元」為必填。課程沒有單元時，新增表單改顯示「請先建立課程單元」及前往單元管理入口。
- 教師可在每張教材卡直接選擇另一個正式單元，沿用 `PUT /units/activities/material/{id}`。學生只讀。
- 既有 `unit_id IS NULL` 教材顯示於醒目的「未歸類教材」相容區；教師可移入單元，但新介面不可再把教材改回未歸類。
- 課程首頁／課程單元頁繼續顯示教材、測驗與作業；本次只調整教材管理的收納方式，不拆除其他教學活動的單元歸屬。

## 資料與 API 退役

- 使用者確認歷史 tag 已無用途，新增 migration 實體刪除 `course_resources.tags` 與 `tags_version`；既有 tag 值不可復原。Migration 歷史與既有 audit event 保留，但不再含可使用的教材 tag 狀態。
- 移除 `PUT /api/courses/{course}/resources/{id}/tags`、教材清單 `tag` 查詢、檔案／YouTube 建立 payload 的 tags 欄位，以及 `ResourceTagPolicy`、前端 tag 工具與相關測試。舊客戶端呼叫退役端點將收到 404；不新增相容轉送或隱藏欄位。
- 新教材 API 後端要求 `unitId` 且驗證單元屬於同一課程；避免繞過前端建立未歸類教材。既有未歸類資料不批次猜測或刪除。
- 新增一份 schema migration 退役 tag 欄位，不新增資料表。現有 Migration 030 已為升級時的舊活動建立相容單元並回填，大部分既有教材可直接按單元呈現。
- 教材日期、摘要、逐字稿、通知、預覽、下載、互動、學習計時、統計及授權全部保留。

## 驗證

- 前端測試：不出現 tag UI；依單元順序分組；新增教材必選單元；無單元時顯示引導；教師可移動教材；學生無移動控制；未歸類相容區正常。
- 後端測試：Migration 後 tag 欄位不存在；舊 tag 端點不存在；檔案與 YouTube 缺少／跨課 unitId 均拒絕；有效單元可建立；既有未歸類教材仍可讀及移入單元。
- 回歸：教材預覽、下載、摘要、逐字稿、通知、學習時間與學生可見範圍保持正常。
- 只在既有 7173 建置與驗收，不建立其他埠或預覽環境。
