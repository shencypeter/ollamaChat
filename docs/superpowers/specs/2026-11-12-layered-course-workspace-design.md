# 課程分層工作區設計

日期：2026-11-12  
狀態：已於 2026-11-12 由使用者確認

## 意圖

以使用者提供的 `teacher-course-creation-flow.html` 作為資訊架構與瀏覽流程參考，將現有 E-learning 從「課程內所有功能平鋪在同一側欄」調整為「平台 → 課程 → 單元 → 教學活動」的分層工作區。目的是讓教師與學生永遠清楚目前位於哪一門課、哪一個單元，以及返回上一層的位置，同時保留既有討論、分組、批改、成績與授權功能。

參考 HTML 只提供結構與互動靈感；其中的固定週次、教材標籤、假資料、必須先建教材才能建測驗，以及連鎖刪除規則，不視為產品需求。

## 目標

- 課程入口只負責選課程、建立課程及快速生命週期管理。
- 課程首頁以單元清單與近期教學活動為主要內容，不再重複展示一套平鋪功能選單。
- 教師與學生點選單元後進入聚焦的單元工作區；教材、一般作業、PDF 作業、隨堂／課後測驗及其批改入口都依單元排列。
- 頁首、側欄與麵包屑清楚顯示課程和單元脈絡，並提供左箭頭返回上一層。
- 教師建立或編輯教學活動後回到原單元，避免錯置。
- 保留既有資料、URL 相容性、角色授權與學生視角預覽。

## 非目標

- 不建立第二套課程、單元、評量或成績資料模型。
- 不重做討論、分組、PDF 小組作業、互評、成績簿或學生視角的核心業務邏輯。
- 不強制單元對應週次。
- 不恢復歷史教材標籤。
- 不把期中考、期末考等正式考試塞入一般單元。
- 不允許用前端隱藏取代後端課程／角色授權。

## 反目標

- 同時保留兩套互相競爭的課程側欄或建課精靈。
- 讓教師從單元頁跳出課程脈絡後才建立或批改內容。
- 為了貼近參考稿而破壞既有深層連結、舊課程或已提交資料。
- 對有成員、活動、作答或成績的課程／單元進行破壞性連鎖刪除。

## 現況與限制

- 現有 `CourseDetailView.vue` 以 `?section=` 切換課程首頁、單元、教材、正式考試、學員、分組、討論、成績、統計及設定。
- `CourseUnits.vue` 已能讀取、建立、編輯、排序與刪除空單元，也能把既有教材與評量指派至單元。
- 教材、線上作業、線上測驗及 PDF 作業已有獨立深層路由；不可破壞既有書籤與通知連結。
- 教師可切換學生預覽；學生預覽不可寫入正式作答或學習紀錄。
- 課程討論、學員與分組、成績及統計是課程層資源，不屬於單一單元。
- 普通作業與測驗應歸在單元；正式考試保留課程層入口。
- 單元刪除仍僅允許空單元；課程刪除仍僅允許完全空白草稿，其他情況使用封存。

## 考慮過的方案

### A. 分層工作區（採用）

保留現有後端模型與深層活動路由，新增明確的單元工作區路由與導覽狀態。課程層側欄只放課程層功能；教材與一般評量從單元進入。

優點是符合參考稿的空間層級，又能兼容既有資料與功能。代價是需要整理目前 `?section=resources`、`?section=assessments` 的入口與返回位置，並補齊單元工作區的載入與測試。

### B. 額外的「課程建置模式」

保留原本平鋪側欄，另加一個逐步建課模式。改動較小，但會產生兩套導覽與兩種建立入口，教師容易不知道資料應從哪裡管理，因此不採用。

### C. 完全複製參考 HTML 的逐步精靈

所有建立與瀏覽都必須逐層返回清單。視覺最接近參考稿，但不適合日常討論、批改、成績與學員管理，也會大幅改寫既有路由，因此不採用。

## 導覽與畫面結構

### 1. 平台層

未進入課程時，左側只顯示：

- 我的授課。
- 學生視角・我的修課。
- 管理後台（管理員且非學生預覽時）。

課程卡片保留快速修改名稱、公開草稿、進入設定、封存／安全刪除等既有能力。

### 2. 課程層

進入課程後，側欄最上方固定顯示：

- 左箭頭「返回我的授課」或「返回我的修課」。
- 醒目的課程名稱、代碼、學期及課程狀態。
- 教師可用的學生視角切換。

課程層導覽調整為：

- 課程內容（同時是單元清單與課程工作區，不另設重複的「教學單元」頁）。
- 正式考試。
- 學員管理（教師／授權助教）。
- 課程分組／我的小組。
- 課程討論。
- 課程總成績／我的成績。
- 學習統計／我的學習歷程。
- 課程設定（教師／授權助教）。

「教材管理」不再是課程層主要側欄項目。既有未歸類資料仍可從課程首頁的相容性區塊處理，不隱藏也不遺失。

### 3. 課程內容工作區

課程的預設首頁就是課程內容工作區。上方顯示課程摘要、狀態與教師設定圖示；主體依排序顯示完整單元卡片。每張單元卡片顯示：

- 單元名稱與說明。
- 教材、作業、測驗數量。
- 草稿／可用／已結束活動摘要。
- 進入單元按鈕。

教師另可新增、編輯、排序及刪除空單元。管理操作不與學生主要閱讀動線混在同一列。

不再保留另一個內容幾乎相同的「教學單元」側欄頁。既有 `?section=units` 相容轉向課程內容工作區，並在需要時定位至單元管理區；舊連結不失效。

### 4. 單元層

新增 canonical 路由：`/courses/:courseId/units/:unitId`。進入後側欄／頁首脈絡顯示：

- 左箭頭「返回教學單元」。
- 課程名稱。
- 目前單元名稱與單元序號，不強制週次。

進入單元時不換成一套孤立側欄。側欄上方切換為單元脈絡並提供「返回課程內容」，下方仍保留討論、分組、成績等課程層入口；因此使用者可聚焦單元，也不會被困在單元內。單元內容是此狀態的選取項目。

主體依 `sortOrder` 顯示混合活動清單：

- 教材。
- 線上作業。
- PDF 作業。
- 隨堂／課後測驗。

教師可在此新增活動、調整順序、編輯設定及進入批改。學生只看到其可存取狀態、截止時間、提交／完成狀態與已發布成績。

活動詳細頁維持既有深層 URL；進入時帶入或從 API 還原 `unitId`，其返回箭頭回到所屬單元。沒有 `unitId` 的舊資料回到課程的「未歸類活動」區塊。

### 5. 課程層功能的歸屬

- 討論區屬於整門課，維持討論串側欄＋右側內容的既有模式。
- 學員與分組屬於整門課。
- 成績簿整合所有單元活動及正式考試，仍屬於整門課。
- 正式考試保留課程層入口，只放期中考、期末考等由教師明確標記為「課程層正式考試」的評量。`UnitId` 為空不等同正式考試；舊的未歸類評量仍留在相容性區塊，避免錯誤歸類。
- 學習統計可由課程總覽再下鑽至單元或活動，不改變其存取權限。

## 教師流程

1. 從「我的授課」進入課程。
2. 在課程首頁建立或選擇單元。
3. 進入單元後新增教材、作業或測驗。
4. 儲存後返回同一單元工作區，確認位置與排序。
5. 從活動列進入內容管理或批改；返回時仍回到該單元。
6. 從課程層導覽管理討論、學員、分組與成績。

## 學生流程

1. 從「我的修課」進入已公開且有權限的課程。
2. 在課程首頁依排序選擇單元。
3. 在單元工作區依順序閱讀教材與完成活動。
4. 進入活動後，返回同一單元繼續下一項。
5. 從課程層導覽查看討論、我的小組、成績與學習歷程。

教師的學生視角使用相同學生流程，但維持既有唯讀／練習隔離規則。

## 資料與 API

第一階段優先重用現有 `CourseUnit`、活動 `UnitId` 與排序 API。若現有活動排序只支援單元排序、不支援跨類型活動排序，需以相容 migration 新增單元內的共同排序欄位；既有資料以原建立時間及類型內排序穩定回填。

正式考試若尚無明確的課程層旗標，新增相容欄位而不以 `UnitId == null` 推斷。既有資料預設不是正式考試；教師可從未歸類區塊將其移入單元或明確提升為正式考試。

課程與單元 API 必須繼續驗證課程範圍、教師／助教授權及學生 enrollment。單元工作區 API 不接受只憑 `unitId` 存取資料；必須同時驗證 `courseId` 與單元歸屬。

不移除既有 `?section=resources` 或舊深層連結。舊入口採相容轉址或顯示未歸類資料，等確認沒有外部依賴後才可能淘汰。

## 錯誤與邊界處理

- 不存在或不屬於該課程的 `unitId` 回傳 404，不洩漏其他課程資料。
- 無權限的課程／單元維持 403 或現有安全導向。
- 活動所屬單元被修改後，舊連結仍可開啟活動，返回位置依最新歸屬計算。
- 單元含活動時不可刪除；介面說明阻擋原因。
- 未歸類舊活動可讀取並由教師移入單元，學生端不得因遷移中資料而看見未發布內容。
- 返回位置無法取得時，安全退回課程首頁，不使用瀏覽器歷史作為唯一返回機制。

## 驗證

- 單元工作區路由、課程／單元脈絡與返回連結的元件測試。
- 教師與學生側欄項目、學生視角切換及授權差異測試。
- 教材、線上作業、PDF 作業、測驗從單元進入與返回的整合測試。
- 未歸類舊資料與舊 URL 相容測試。
- 單元排序、活動排序、刪除限制及跨課程 `unitId` 防護測試。
- 桌面與窄螢幕導覽測試。
- 執行現有前端測試、後端測試、建置及 7173 單一環境 smoke test。

## 交付邊界與實作者裁量

- 圖示、間距、卡片細節沿用現有設計 token 與 Lucide 圖示，由實作者在不改變層級的前提下決定。
- 第一批先完成導覽、單元工作區與既有活動返回；資料 migration 僅在現況確認缺少共同活動排序時新增。
- 不在這次工作中新增公告、開放選課、討論進階功能或新的學習分析模型。
- 實作後同步更新 `.ai/elearning.md`、`.ai/agents.md` 與 `.ai/history.md`。
