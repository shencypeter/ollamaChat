# 單元評量與批改工作區設計

## 目的

一般課堂作業、隨堂／課後測驗及其批改入口應跟著課程單元呈現；課程外層的評量入口改以期中、期末等正式考試為主。教師批改線上作業時，以討論區相同的雙欄閱讀模式快速切換全班交卷。

## 相容原則

- 沿用 `course_units`、`assignments`、`submissions`、`submission_revisions`、`grades` 與既有授權 API，不建立第二套作業或成績資料。
- 單元頁的評量活動直接連到既有作業頁；教師會看到「批改」動作，學生只看到作答入口。
- 外層評量頁保留既有資料與連結，但文案及主要區塊突出正式 `exams`；不搬移或刪除舊作業。
- 未交卷學生仍是名冊中的未交狀態。右側只依題目渲染唯讀空白卷，不建立 Submission，也不可給分。
- Demo 交卷使用現有有效學生帳號，寫入正式 submission／revision／answer 結構；種子可重跑且不發布成績。

## 批改工作區

- 左欄分為「已交卷」及「未交卷」，兩組內依學號、姓名排序；已交卷永遠在上。
- 選取已交卷學生後，右側沿用 `TeachingPanel` 顯示版本、答案、自動批改與人工評分。
- 選取未交卷學生後，右側顯示該份作業題目與空白答案，標示唯讀且無評分控制。
- 桌面採兩欄，窄螢幕改為上下排列，保留鍵盤可操作的原生按鈕。

## Demo 資料

- 僅處理開發環境中具課程教師、有效學生及已發布個人線上作業的課程。
- 對尚未交卷的學生建立一份可辨識課程與題意的合成答案、提交快照及客觀題計分結果。
- 不覆寫既有作答、不處理草稿／小組作業、不發布成績；稽核工具驗證每份目標作業的有效學生均有正式交卷。

## 取捨

考慮過新增批改專用 API 與另建批改頁，但現有 class-roster 已提供完整名冊，`TeachingPanel` 也已具備真正評分能力。採前端工作區組合既有 API，變更最小且不會讓兩套流程分歧。
