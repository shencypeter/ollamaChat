# 課程編輯與教學單元

更新：2026-11-11。這是目前程式與 Migration 030 的現行規格；單元是教學內容層級，不是 Migration 010 曾使用、並於 016 退役的班別 `course_sections`。

## 現況盤點

- 課程已有建立、開放、教師／助教／學生名單、逐課 TA 權限、封存狀態及教師／學生分離導覽；本次補齊基本資料編輯、安全刪除與明確封存操作。
- 教材已有檔案、YouTube、標籤、授課日期、教師摘要、逐字稿、互動與學習時間；測驗使用 `assignments`，PDF 作業使用 `report_assignments`，兩者已連動同一成績簿。個人／小組繳交、互評、同分共識、評分草稿及發布保持原流程。
- 舊 `exams` 表仍保留相容資料，但目前主要線上測驗流程是 `assignments`；本階段不重建正式考試系統。

## 資料模型與升級

`course_units` 保存 `name`、`description`、`sort_order`、`version`、`created_at` 及 `updated_at`。排序在同課程內唯一並延後到交易提交時檢查，讓完整重新排序可原子完成。

`course_resources`、`assignments`、`report_assignments` 與相容用 `exams` 新增 nullable `unit_id`，採 `(unit_id, course_id)` 複合外鍵，資料庫會拒絕跨課程錯誤歸屬。nullable 是匯入與舊客戶端的相容邊界；教師介面會顯示「未歸類教學活動」。

Migration 030 對每門已有活動的舊課程建立一個「既有教學活動」單元，原地回填所有活動。活動 ID、作答、PDF、分組快照、互評、成績與稽核均不搬移或重建。`courses` 另加入 `version` 與 `updated_at` 供課程編輯衝突控制。

## 權限與生命週期

- 有效課程成員可讀取單元；學生看不到草稿測驗／作業，且小組 PDF 仍依原 audience 規則過濾。
- 課程教師可新增、編輯、排序、移動活動及刪除空單元。助教與學生不能改單元，這是本階段的保守預設。
- 只有課程擁有者可編輯課程基本資料、封存或嘗試刪除。
- 只有完全空白、未開放、除擁有者外沒有成員且沒有單元／活動／成績／群組／案例／問答的草稿可實體刪除。其他課程必須封存；封存保留全部歷史並停止管理寫入。
- 單元有任何教材、測驗、PDF 作業或舊考試時不可刪除，必須先移動活動。所有變更保留 audit event。

## 介面與 API

課程側欄新增「單元管理／課程單元」。課程首頁依排序顯示單元及其中的教材、既有線上作業、線上測驗、PDF 作業；教師可在單元管理建立、編輯、上下排序與調整活動歸屬。新增檔案或 YouTube 教材時可直接指定單元；評量亦可透過單元管理安排，後端建立 API 已接受並驗證 `unitId`。

主要 API：

- `GET /api/courses/{course}/curriculum`
- `POST /api/courses/{course}/units`
- `PUT|DELETE /api/courses/{course}/units/{unit}`
- `PUT /api/courses/{course}/units/reorder`
- `PUT /api/courses/{course}/units/activities/{kind}/{activity}`
- `PUT /api/courses/{course}`、`POST .../archive`、`DELETE ...`

## 本週 Demo 驗收

1. 以課程擁有者進入「課程設定」，編輯課程名稱、代碼、學期或班別並儲存。
2. 開啟「單元管理」，將自動升級的「既有教學活動」改名並補充說明。
3. 新增第二個單元，以上下箭頭調整順序；建立教材時指定該單元，或將既有測驗／PDF 作業移入。
4. 返回課程首頁，確認畫面依單元順序呈現教材與評量，點選後仍進入原教材、作答或 PDF 流程。
5. 切換學生視角，確認只讀單元、看不到草稿評量，且小組作業仍只顯示本人小組。
6. 嘗試刪除有活動的單元，應收到限制；移空後才可刪除。
7. 嘗試刪除已有資料的課程，應要求改用封存；封存後歷史仍可讀且管理寫入被拒絕。

## 後續規劃

課程公告、開放選課、進階討論、正式考試重整、拖曳排序與完整單元完成度／學習分析未納入本階段。現有課程問答、通知、教材學習時間及學習歷程保持運作，但尚未新增單元層級統計。
