# 11/15 展示：UX／導覽整合

## 稽核與實作範圍

現有 Vue 3、Vue Router、Lucide、共用 CSS 與 ASP.NET API 保留。沒有新增依賴、Migration 或替代成績系統。

| 原狀況 | 修正 |
| --- | --- |
| 登入直接進入課程清單，舊首頁以裝飾性 AI banner 為主 | 登入首頁改成可操作的教學／學習儀表板，沿用課程、通知、繳交與學習歷程 API |
| 每份作業各佔全班成績表一欄 | 教師預設固定欄數摘要，可切換逐筆明細、依單元／類型／活動篩選 |

## 導覽

個人首頁 → 我的授課／我的修課 → 課程內容 → 單元 → 教材／測驗／作業。課程層繼續保留正式考試、分組、討論、成績、統計與設定。帳號選單可隨時返回 Portal。

個人學習歷程只彙整當事人仍具有有效學生資格的課程；包含封存課程。教授的唯讀學生預覽不是正式修課，不會憑空產生個人成績／歷程。

## 保留的規則與設計決策

- 後端仍是授權、課程歸屬、成績發布與計算的唯一依據。後續使用者明確核定移除課程項目權重，已同步調整後端算法。
- 各項百分制後等比平均；課程總成績與調分採後端結果。空白不計、0 分計入。既有已發布總成績快照保留，重新發布才採新算法；測驗內題目配分保留。
- 成績簿沒有提交狀態欄位，空白分數不能推論成未繳交；畫面會使用未登錄／未發布並連結原評量名冊。
- 獨立正式考試的結果沒有可安全連接成績簿學生 ID 的 DTO；不按姓名硬接。既有成績簿期中／期末項目保留，其他正式考試由明確入口進入原考試畫面。
- 小組 `off/simple/consensus` 的意義不變；consensus 同時啟用互評與同分調查。獨立「只做同分調查」需要後端擴充，本次沒有用新文字假裝已有此功能。
- 指定小組名冊 DTO 未提供 submission ID，因此名冊與批改紀錄分開呈現，不按可能重複的小組名稱硬接。
- 系統目前沒有課程公告資料模型／API，首頁不展示虛構公告。通知只展示既有正式課程通知。

## 11/15 驗收順序

1. 教師登入，確認直接進入我的首頁；檢查授課、待批改、近期繳交及無回覆討論入口。
2. 右上角使用者選單 → 我的首頁（Portal）；進入課程 → 單元 → 活動，核對麵包屑及返回入口。
3. 課程成績：先看固定欄數概覽，再切成績明細，選單元／類型／活動；確認 0 分與未登錄不同。
4. 展開成績管理，確認不再顯示課程權重，人工評分、課程調分及發布流程仍可操作；正式考試仍有獨立入口，測驗題目配分仍在命題畫面調整。
5. 開啟小組 PDF 作業，查看完整指定名冊、未交組、基礎成績與個別最終草稿；檢查調整原因與互評參考文字。
6. 學生登入，確認跨課待辦、課程進度與最近已發布成績；由單元進入教材／作業。
7. 我的成績：只出現一次個人成績表，依單元與類型篩選；不得看到其他人的分數。
8. 我的學習歷程：跨課／學期查詢；回到課程學習進度則沒有跨課篩選。
9. 390px 窄版確認選單、篩選、表格、主要操作均可使用。

## 後續與驗證限制

P1：公告持久化、獨立同分調查模式、正式考試與成績簿的 ID 級整合、完整小組名冊狀態（待評／已評）需要相應後端 DTO／規則。這些功能不能僅靠介面文字實現。

P1：大型課程儀表板目前重用既有 API，後續可增加授權的專用聚合 endpoint；個人歷程的既有教材時間記錄仍需與靜態點閱事件統一整合。

P2：低優先視覺裝飾與動畫。
