# 第二階段：規準導向申論草稿回饋草案

日期：2026-11-09。狀態：後續設計，**未啟用一般測驗／作業AI**；不屬本次11/15新增開發承諾。

## 現況與目標

一般評量的FormativeFeedbackController目前GET／POST均403，符合先前「作業全部停用AI，保留獨立入口」決策。獨立案例的StudioWorkflow已有答案版本、教師重點清單及文字回饋／重試；獨立AI入口也存在。這些不等於任意申論題的教師規準整合已完成。

目標是教師對指定申論評量設定明確規準並選擇是否開啟草稿建議；學生主動要求對已存本人草稿提供形成性文字回饋。正式成績維持人工申論評分／既有客觀規則批改，不使用AI分數。

## 建議流程與資料邊界

1. 教師保存題目、教學回饋規準及版本；區分「可提供形成性建議的規準」與「不得向學生揭露的標準答案／評分參考」。不能直接把現有私密gradingGuidance或完整答案鍵送入學生回饋後宣稱無洩漏。
2. 每份評量預設關閉；未經後續明確授權，不改目前403。考試模式／是否允許草稿AI、時間及次數限制先由教授定案。
3. 學生儲存本人非空白申論草稿，選擇請求AI；不可代他人請求，練習與正式命名空間隔離，不以觀摩區作答充當本人答案。
4. 後端驗證課程／題目／目前草稿版本與開關，組合允許的題幹、必要且已確認可用的案例素材、回饋規準、本人作答及固定不代答指令；模型配置沿用對應Ollama profile，不能以某模型修正覆蓋其他模型。
5. 輸出優點、缺漏、證據不足及下一步修訂方向；不提供完整代答或正式評分。伺服器驗證結構、長度、HTML安全，輸入文字是資料而非可覆寫系統的指令。
6. 回饋綁草稿版本／規準版本／模板與模型配置版本、請求及完成時間／狀態。學生修訂另存新版本，舊回饋標示已非目前草稿，不靜默套用。
7. 逾時／失敗不變動草稿或成績；有界重試、防重複pending與可理解錯誤。教師是否可讀未正式提交的AI草稿／回饋不得擴權；沿用目前草稿私人、教師只看正式提交及其允許回饋，除非另核定。

## 資料與研究政策待辦

教授／校方需確認允許的個案資料範圍、去識別責任、學生告知／使用授權、存取對象、保存及刪除期限、研究／IRB適用性與核准流程。上述為開發前確認事項，不在此文判定法律適用或核准狀態。內網Ollama不等於資料與研究要求已完成；日誌／稽核不保留作答正文、敏感案例或原始模型思考。

不得把教材逐字稿自動當成可送模型的臨床資料；教師上傳素材不等於允許研究或AI處理。示範先用合成或已確認可用素材，不修改正式既有作答。

## 後續驗收與未定項

- 關閉時原端點仍拒絕；學生／教師跨課、代他人或讀私人草稿均拒絕；只有許可的評量與時間可請求。
- 任一回饋能追溯其草稿、規準、模板及模型配置；修訂後正確標為舊回饋。
- 提示注入、洩漏答案鍵、代寫、AI分數、敏感資料輸出以合成測例驗證；模型真實輸出需另有品質評閱，不只跑HTTP成功。
- 模型逾時、重複點擊、服務中斷與重試不建立重複pending／結果，不丟草稿或寫入正式成績。
- 待定：開放哪些評量、規準結構／公開範圍、資料保存／刪除政策、每版次數、考試禁用、實際模型與12/15／年底驗收項目。
