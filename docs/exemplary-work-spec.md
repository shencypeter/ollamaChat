# 優良作業觀摩規格草案

日期：2026-11-09。狀態：未實作；依[會議差距入口](meeting-2026-11-06-gap-spec.md)D1／D2確認後開發。會議方向為教授選取、匿名公開給同課學生；以下流程及資料設計為提案。

## 目標與首批來源

課程增加「優良作業觀摩」區，教師從已正式提交且完成評分的作答建立觀摩草稿，學生不能自行分享。觀摩不更動原作答、原成績、標準答案、AI紀錄或私人草稿。

建議首批支援目前線上測驗的申論題（可選一題或數題）及PDF報告；純客觀答案展示、獨立案例AI作答、舊未連動評量、練習提交不納入首批。來源須綁定不可變提交版本／PDF繳交ID，不從最新可變草稿直接產生。

## 權限與狀態

| 動作 | 學生 | 本課助教 | 本課教師 | 未任課管理員／跨課者 |
|---|---|---|---|---|
| 讀已發布匿名副本 | 本課有效學生可 | 可 | 可 | 不可 |
| 選來源、準備／編輯草稿、預覽 | 不可 | 可 | 可 | 不可 |
| 最終發布 | 不可 | 待D1；草案預設不可 | 可 | 不可 |
| 撤下以阻止繼續存取 | 不可 | 草案可 | 可 | 不可 |
| 讀原作答與作者映射 | 僅原有本人權限 | 依原教學權限 | 依原教學權限 | 不可 |

狀態：draft → published → withdrawn。撤下可另存新草稿、重新審查後再發布；published內容不可直接覆寫，編輯建立待發布版本，學生持續看原發布快照；新版本發布以版本檢查原子切換。封存課程建議唯讀已發布項目，但仍允許有權教師／助教為隱私原因撤下；停止新增／編輯／發布。

## 準備與發布流程

1. 伺服器驗證課程、來源與正式提交版本屬本課，評分已完成且正式成績已公布。只選需展示部分，不複製整份評量及所有答案。
2. 建立不可對學生見的觀摩草稿：教師自訂標題、展示題幹或必要背景、已去識別作答、教學說明。題目／背景也需檢查個案識別資訊；不自動公開原始個案全文。
3. 文字以教師可編輯副本整理；PDF必須另外上傳經確認的展示副本，不能只改檔名或直接使用學生原始PDF下載URL。第一批只沿用20MB內PDF驗證，不宣稱平台自動遮罩、移除metadata或完成匿名檢查。
4. 教師預覽**學生實際會收到的DTO與附件**；檢查姓名、學號、email、封面、文件metadata、個案細節、內文及附件，另確認作答使用授權依據。
5. 教師確認「已去識別檢查」「使用授權已確認」「無洩題／仍可作答影響」，記錄確認者／時間／政策或授權紀錄識別。確認不是取代正式授權或研究倫理程序；未確認不接受發布。
6. 建議發布條件為來源評量已關閉，且無開放補交／再作答；僅到截止或成績已公布不足以自動視為無洩題風險。若教授需要期中提前展示，另核定例外，不由前端自行繞過。
7. 學生讀發布快照，並可閱讀教師教學說明。成績更正或學生修訂不自動覆寫已審查內容；需新版本及重新確認。
8. 發現隱私／授權問題，可立即撤下；列表、詳情與附件均重新檢查發布狀態，舊URL不可繼續下載。

## 匿名與資料最小化

學生回應僅允許觀摩ID、標題、教師確認的題幹／背景、作答、教學說明、發布時間、展示附件入口。預設不列原分數／名次。禁止作者ID／姓名／學號、來源提交ID、原附件名稱／URL、內部備註、授權文件、私密標準答案、AI提示或原始回饋、修訂歷程。

不產生跨項目穩定學生代號；有需要只顯示項目內「範例一」等標題。內部來源映射僅供有權教師追溯，不能混在學生DTO隱藏欄。教學端不得以練習視角查真實來源。匿名為人工確認的展示內容，不能承諾讀者無法由文意推知作者。

撤下只能停止後續平台存取，不能收回學生已讀、已截圖或已下載的內容。附件使用私有授權端點、nosniff／附件下載，回應no-store；不放公開靜態目錄、不提供不受狀態檢查的永久分享URL。

## 建議資料及 API

新增獨立觀摩項目／版本／展示附件資料，不在submissions增加is_public擴大原答案存取。每項綁course_id及私有來源型別／版本；公開快照和內部確認／來源欄分開。版本包含expectedVersion、發布／撤下者與時間、審查確認版本。編輯使該草稿原審查失效；不得用同意舊版發布新內容。稽核只記ID／動作／版本，不記真實作答本文。

提案路由（尚不存在）：

- GET /api/courses/{course}/showcases：學生只列published；教學端另帶授權草稿列表。
- POST /api/courses/{course}/showcases：教學端選正式來源建draft。
- GET／PUT /api/courses/{course}/showcases/{id}：依角色回不同允許欄位；PUT帶expectedVersion。
- POST .../{id}/preview：教學端預覽學生快照；不開學生讀來源權限。
- POST .../{id}/attachments：另傳展示PDF，綁草稿版本。
- POST .../{id}/publish：教師提交同一版本的審查確認，交易驗證來源、授權、關閉狀態。
- POST .../{id}/withdraw：教師／助教撤下；冪等，保留稽核。
- GET .../{id}/attachment：逐次授權，僅當前可見發布附件；草稿附件另限教學端。

來源已刪除／撤銷使用授權／課程關係失效時，不可繞過授權。來源刪除及帳號刪除的保留政策需與校方政策定案；實作先以FK保護、撤下阻擋公開，不自動級聯清除原成績或審查依據。重新發布需新版本檢查，過期409，跨課／不可見ID對學生不洩漏存在性。

## 驗收

| ID | 情境 | 預期 |
|---|---|---|
| OBS-01 | 教師選本課正式已評申論或PDF | 建立私有草稿；原答／成績不變 |
| OBS-02 | 選私人草稿、練習、未評、外課或已作廢版本 | 拒絕，不產生公開副本 |
| OBS-03 | 學生列草稿或直接猜ID／附件URL | 無內容，無來源／作者洩漏 |
| OBS-04 | 未完成三項確認，或評量仍可作答 | 發布拒絕；助教發布依D1定案 |
| OBS-05 | 修改審查過的內文／PDF後沿用舊確認 | 拒絕，須重新確認新版本 |
| OBS-06 | 同課學生讀published、跨課及未任課管理員讀 | 前者僅匿名快照，後者拒絕 |
| OBS-07 | HTML、惡意檔名或原附件連結混入 | 文字安全處理；不公開原附件／主動內容 |
| OBS-08 | 撤下後再讀列表／詳情／舊附件連結 | 全部不可存取，稽核保留 |
| OBS-09 | 同時編輯／發布、原作答後續變動 | 過期409；已發布快照不悄悄改變 |
| OBS-10 | 封存或退出課程後存取／撤下 | 依上列權限；退出學生拒讀，隱私撤下仍可 |

測試用合成作答及合成PDF；需人工以學生DTO／PDF檢閱匿名內容，不只檢查UI姓名是否隱藏。正式公開前，D1／D2與教授提供的已授權範例必須確認。
